# 压力测试指标与展示

## 1. 消息模型

压力客户端发送 `Test` 类型，服务端以相同类型回传负载：

```json
{"sequence": 123, "data": "0123456789abcdef..."}
```

- `sequence` 用于匹配请求和回显，检测缺失、重复和非预期响应。
- `data` 由场景开始时一次性生成的固定模式构成，不使用随机数据。
- 接收端检查序号、`data` 长度和内容，不打印完整正文。
- 消息大小按 `8 字节头部 + JSON 编码长度` 计算。

## 2. 运行时指标

| 指标 | 含义 |
| --- | --- |
| Target MiB/s | 场景配置的目标应用协议输入速率 |
| Actual MiB/s | 客户端实际完成发送的协议帧字节数除以时间 |
| Echo MiB/s | 客户端完整接收并验证的回显帧字节数除以时间 |
| Sent msg/s | 每秒完成发送的请求数 |
| Echo msg/s | 每秒完整验证的回显数 |
| Outstanding | 已发送但尚未收到匹配回显的请求数 |
| RTT | 从开始发送请求到完整收到对应回显的时间 |
| Send duration | 单次 `send_message()` 调用耗时，可反映 TCP 背压 |
| Drain time | 停止生成新请求后，Outstanding 降为 0 的时间 |
| Errors | 发送、接收、超时、类型、序号和内容校验错误 |

RTT 和 Send duration 都记录 P50、P95、P99 和最大值。运行时显示最近 1 秒的窗口统计，场景结束后显示全场景统计。

CPU 和进程 RSS 不作为跨平台核心判定项，只作为可选的平台观测数据。

## 3. 运行时反馈

禁止逐条打印成功消息和回显正文。每秒输出一行聚合结果：

```text
时间  Actual    Echo      Sent/s  Echo/s  Outstanding  RTT-P99  Send-P99  Errors
 12s   9.84MiB/s 9.77MiB/s 10072   9998    74           18.2ms   0.7ms     0
```

不使用反复覆盖同一行的终端控制序列，保证输出可以跨平台使用并可以直接重定向到文件。

成功事件不打日志。每类错误只立即打印前少量样本，后续相同错误只累加计数，避免错误风暴本身成为性能瓶颈。

## 4. 场景摘要

每个场景结束后输出固定格式摘要：

```text
Profile                 small
Frame size              1.00 KiB
Target / Actual / Echo  10.00 / 9.99 / 9.97 MiB/s
Sent / Echoed           307214 / 307214 messages
Peak outstanding        183 messages
RTT p50/p95/p99/max     2.1 / 8.7 / 16.4 / 38.2 ms
Send p50/p95/p99/max    0.1 / 0.3 / 0.6 / 4.8 ms
Drain time              0.21 s
Errors                  0
Correctness             PASS
Load state              SUSTAINABLE
```

结果分为两个独立结论：

- `Correctness`：`PASS` 或 `FAIL`，反映消息完整性、数量和连接是否正确。
- `Load state`：`SUSTAINABLE` 或 `SATURATED`，反映目标速率下是否出现吞吐平台、延迟和积压持续增长。

达到性能上限不等于正确性失败。

## 5. 结果文件

控制台用于即时观察，结构化文件用于比较和绘图：

- `timeline.csv`：每场景每秒一行，保存吞吐、延迟和在途请求时间序列。
- `summary.csv`：每场景一行，便于对比大小消息和多个目标速率。
- 后续阶段可根据上述文件生成自包含 HTML 报告，但不让绘图逻辑影响压力发送过程。

## 6. 可视化

套件模式主要生成三张图：

1. 目标输入 MiB/s 与实际发送、回显 MiB/s，用于寻找吞吐开始走平的拐点。
2. 目标输入 MiB/s 与 P99 RTT，用于寻找尾延迟快速上升的拐点。
3. 运行时间与 Outstanding，包含停止发送后的排空阶段，用于区分稳定、短暂积压和持续积压。

大消息和小消息使用相同坐标轴对比。错误分类、最大值和正确性结果使用表格，不额外绘图。

## 7. 判定标准

以下情况判定 `Correctness=FAIL`：

- 回显类型、序号、数据长度或内容不匹配。
- 回显缺失、重复或出现未发送的序号。
- 发送、接收或协议发生错误。
- 连接意外中断或程序崩溃。
- 停止发送后未在 `drain-timeout` 内收到全部回显。

以下现象表明可能进入 `SATURATED`：

- Echo MiB/s 不再随目标速率上升。
- P99 RTT 或 Send duration 随时间持续上升。
- Outstanding 在发送阶段持续单向增长。
- 停止发送后需要明显的排空时间。
