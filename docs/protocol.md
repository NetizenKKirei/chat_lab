# 通信协议

## 1. 基本约定

客户端与服务端使用 IPv4 TCP，消息采用固定 8 字节头部加 UTF-8 JSON 对象负载。TCP 是字节流，一次发送或接收不等于一条消息。每帧按头部给出的长度读取，不依赖换行分隔，也不额外传输字符串终止符。

## 2. 帧结构

| Index | 字段 | 长度 | 内容 |
| --- | --- | --- | --- |
| 0～1 | 魔数 | 2 字节 | ASCII `CH` |
| 2 | 版本 | 1 字节 | 固定为 `1` |
| 3 | 消息类型 | 1 字节 | 无符号编号，见下表 |
| 4～7 | 负载长度 | 4 字节 | 无符号 32 位整数，大端序 |
| 8～ | 负载 | 长度字段指定的字节数 | UTF-8 JSON |

版本字段存数值 `1`（`0x01`），不是字符 `'1'`。长度字段为网络字节序，仅计算编码后的 JSON 负载，不包含头部。空对象 `{}` 的负载长度为 2。

例如查询在线列表的完整帧：

```text
43 48 01 02 00 00 00 02 7B 7D
```

接收方先读够 8 字节并校验，再读取指定长度的负载；连续到来的帧按此规则逐条解析。

## 3. 消息类型与响应格式

负载均为JSON对象。

| 编号 | 类型 | 客户端请求字段格式 | 服务端行为 |
| --- | --- | --- | --- |
| 1 | `Login` | `{"username":"alice"}` | 检查用户名和重名情况，为当前连接绑定身份 |
| 2 | `List` | `{}` | 返回当前在线用户名列表 |
| 3 | `Broadcast` | `{"text":"大家好"}` | 投递给其他所有已登录用户 |
| 4 | `Private` | `{"to":"bob","text":"你好"}` | 向目标用户投递讯息 |
| 5 | `Response` | 不允许作为客户端请求 | 服务端返回成功响应 |
| 6 | `Error` | 不允许作为客户端请求 | 服务端返回错误响应 |

服务端响应格式：

| 类型 | 场景 | JSON 示例 |
| --- | --- | --- |
| `Response` | 登录成功 | `{"request":"login","username":"alice"}` |
| `Response` | 在线列表 | `{"request":"list","users":["alice","bob"]}` |
| `Response` | 群发处理成功 | `{"request":"broadcast"}` |
| `Response` | 私聊处理成功 | `{"request":"private"}` |
| `Broadcast` | 发送群聊 | `{"from":"alice","text":"大家好"}` |
| `Private` | 发送私聊 | `{"from":"alice","text":"你好"}` |
| `Error` | 操作失败 | `{"request":"private","code":"DELIVERY_FAILED","message":"目标用户不在线"}` |

客户端发送类型 1～4；服务端发送响应类型 5、6，以及群聊、私聊投递类型 3、4。客户端收到的消息可能是业务响应，也可能是其他用户的聊天投递。

## 4. 请求字段与行为

| 请求 | 必需字段 | 规则 |
| --- | --- | --- |
| `Login` | `username`：字符串 | 1～32 个 ASCII 字母、数字或下划线，区分大小写；在线名称唯一；同一连接只能成功登录一次 |
| `List` | 无，使用 `{}` | 必须登录；返回包含自己的在线名单，按用户名排序 |
| `Broadcast` | `text`：字符串 | 必须登录；正文非空；发给查询目标时在线的其他用户，不回发给发送者 |
| `Private` | `to`、`text`：字符串 | 必须登录；目标名满足用户名格式；正文非空；仅向目标投递，允许目标是自己 |

正文允许空白文字和空格，长度按 UTF-8 字节数计算。服务端根据连接的登录身份生成投递中的 `from`，不采用客户端自行声明的发送者。额外 JSON 字段不参与当前业务处理。

群聊和私聊的发送者收到成功响应或错误响应。群聊没有其他在线用户或部分目标发送失败时返回 `DELIVERY_FAILED`，发送成功的消息不撤回；私聊目标不在线时返回 `USRER_OFFLINE`。成功响应表示发送处理成功，不代表目标已经阅读。

连接结束后释放用户名。`/quit` 是客户端本地命令，不对应额外的协议消息。

## 5. 两层长度限制

| 层次 | 上限 | 检查对象与处理 |
| --- | --- | --- |
| 协议负载 | 4 MiB | 整个 JSON 编码后的字节数；接收端在分配空间前检查，零长度或超限则拒绝并结束连接 |
| 聊天正文 | 1 MiB，即 1,048,576 字节 | 解析后的 `text` 字节数；超限返回 `MESSAGE_TOO_LARGE`，不投递，连接可继续使用 |

等于上限时允许通过长度检查。JSON 字段和转义会增加编码长度，因此必须同时满足两层限制。发送端也检查协议负载上限，超限时本地报错并返回失败，不发送该帧。

## 6. 错误响应与断开规则

`Error` 负载包含三个字符串字段：`request` 是请求名称，`code` 是稳定的错误标识，`message` 是可调整的用户提示。

| 错误码 | 触发条件 | request |
| --- | --- | --- |
| `ALREADY_LOGGED_IN` | 当前连接重复登录 | `login` |
| `INVALID_ARGUMENT` | 字段缺失、字段类型错误、用户名格式非法或正文为空 | `login`、`broadcast`、`private` |
| `USERNAME_TAKEN` | 登录名称已被占用 | `login` |
| `NOT_LOGGED_IN` | 未登录就查询列表或聊天 | `list`、`broadcast`、`private` |
| `MESSAGE_TOO_LARGE` | 正文超过 1 MiB | `broadcast`、`private` |
| `DELIVERY_FAILED` | 群聊无目标、目标离线或投递发送失败 | `broadcast`、`private` |
| `USRER_OFFLINE` | 私聊目标离线 | `private` |
| `UNEXPECTED_TYPE` | 客户端发来有效但不受理的类型，如 `Response` 或 `Error` | `unknown` |


业务校验失败时发送 `Error` 并继续处理请求。魔数错误、不支持的版本、未知类型编号、负载长度非法、无效 JSON 或非对象负载则由协议解析返回失败，服务端清理并关闭连接；这些协议错误当前不保证收到结构化 `Error` 响应。EOF 或系统收发错误也结束连接处理。系统 `errno` 不直接作为业务错误码发送。
